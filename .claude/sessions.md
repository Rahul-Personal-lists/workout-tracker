## 2026-06-29 — Day-order fix (rahul@satel.ca live data) + hardening (#113)

- **Live-data incident:** rahul@satel.ca's active "12-Week Hypertrophy" rendered days out of order (at week 8: Day 52 = Bench, Day 53 = rest-not-squat, Day 54 = incline-not-rest, …). Root cause = the program's `program_days.day_number` order had diverged from intent: `reorderDay`/`swap_day_order` swaps `day_number` but leaves the text `label` stale, and an archived empty "New day" sat wedged at `day_number` 5, leaving live numbers non-contiguous `[1,2,3,4,6,7,8]`. The `label` fields **and** the preset source both still encoded the correct order (Day1 Upper-Str/Bench → Day2 Lower-Str/Squat → Day3 Rest → Day4 Upper-Hyp/Incline → Day5 Lower-Hyp/Good-Morning). **Fixed in the DB** via a self-verifying service-role `tsx` script (two-phase renumber to `1..7` by label, archived day parked at 8) after a dry-run + user confirm. **The Supabase MCP can't reach the prod project (`stwmtvigdbtmmedevqip`)** — it's on a different org; use a service-role script for real-data work (memory: `supabase-prod-db-access`).
- **Hardening — PR [#113](https://github.com/Rahul-Personal-lists/workout-tracker/pull/113)** on `fix/day-order-hardening`: new pure [src/lib/day-order.ts](src/lib/day-order.ts) `planDayOrder` (live days contiguous `1..N`, auto "Day N" labels synced to position, custom labels preserved, archived parked above the live range) + [scripts/smoke-day-order.ts](scripts/smoke-day-order.ts) (6 cases). [program.ts](src/app/actions/program.ts): added `applyDayOrder` two-phase writer (mirrors `renumberExercises`, no-ops when clean); `reorderDay` now array-swaps the neighbor + normalizes — **retires the `swap_day_order` RPC** (left in the DB, unused → no migration); `addDay` inserts at a temp `day_number` then splices at a true **live position** + normalizes (removes the manual descending-shift loop). History labels read live (a past session's "Day N" follows the day's current slot; title/week/date unchanged). No "reset order" UI (a no-op once labels==position).
- **Verification:** `tsc`/`lint` (0 errors; 2 pre-existing `progression.ts` warnings)/`build` green, smoke 6/6, **plus a live end-to-end run on the test account** (Playwright + `scripts/test-otp.ts`): clicking "Move day later" fired the real `reorderDay` and the DB showed the moved day's label synced to its new position; inserting a Rest day "After Day 2" via the real `addDay` produced contiguous `[1..6]` with synced labels; test account restored after.
