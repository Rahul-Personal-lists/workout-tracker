## 2026-05-28 — /program completion states + day auto-advance

- Shipped [#65](https://github.com/Rahul-Personal-lists/workout-tracker/pull/65) on `fix/program-day-completion-state`: `/program` now reaps stale sessions on render (the old `/today` page used to do this; nothing was calling it after `/today` was deleted, so 2h+ orphaned sessions were anchoring the page to yesterday's day via `getNextWorkout`'s in-progress check).
- New `getCompletedSlots(program)` query in [queries.ts](src/lib/queries.ts) returns a `Set<"dayId:weekNumber">`. Derived `SlotState` (`completed | in-progress | today | upcoming`) flows from `page.tsx` → `DayControls` (4-way stage label replaces `isToday: boolean`) → `DayTabs` (per-pill state precedence: selected > in-progress > today > completed > upcoming, with a `Check` icon on completed pills and a `ring-2 ring-accent/40` outline on the today pill).
- Follow-up commit added a "Redo workout" `btn-secondary` button for completed days (same `startWorkout` server call, just different label + style). Resume banner still owns the in-progress state.
- Opened [#66](https://github.com/Rahul-Personal-lists/workout-tracker/pull/66) on `fix/program-stay-on-todays-finished-workout` to short-circuit the cycle advance in `getNextWorkout` when `lastFinished.ended_at` falls on today's date in the user's tz (via existing `dateKeyInTz` + `getUserTimezone`). Verified both paths via Supabase MCP — finish today → stays on Day 1 / COMPLETED, then bumping `ended_at` 25h back → advances to Day 2 / TODAY'S WORKOUT. Subsequently noticed `queries.ts` on main no longer carries the same-day short-circuit; PR #66's status on main is uncertain and may have been reverted or never merged.
- Verification used Supabase MCP to insert + delete test `workout_sessions` rows on the `claude-test@example.com` account, then cleaned up.
